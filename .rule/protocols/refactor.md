# 重构推理协议

执行**重构任务**时请遵循本协议。

1. **梳理现有行为**
理解系统当前的实际运行逻辑。
切勿仅凭借代码表象开展重构。
2. **定位结构性问题**
问题示例：

- 耦合度过高
- 代码重复
- 职责归属模糊
- 可测试性差
- 模块过于庞大
- 抽象设计不合理

3. **明确重构目标**
重构必须具备具体可落地的目标。
目标示例：

- 降低耦合度
- 提升可测试性
- 隔离业务逻辑
- 消除重复代码
- 优化模块边界

> 
> 仅描述 “让代码更整洁” 不足以作为重构目标。

4. **确定不变约束项**
明确规定**绝对不能改动**的业务行为。
5. **设计目标架构**
定义期望的依赖流向与模块职责归属。
6. **增量式落地实现**
优先采用小规模、不改变原有业务行为的修改方式。
7. **校验业务行为**
运行现有测试用例。
必要时补充回归测试覆盖。
8. **回归复核检查**
核查以下维度：

- 对外公开行为
- API 接口行为
- 状态处理逻辑
- 缓存逻辑
- 数据库逻辑
- 权限鉴权
- 性能表现

9. **最终输出报告**
报告需包含：

- 当前存在的问题
- 重构目标
- 不变约束项
- 架构结构改动
- 行为验证结果
- 剩余风险点
