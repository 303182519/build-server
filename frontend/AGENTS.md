# AGENTS.md

This file provides guidance to AI coding agents (Codex / Claude Code 等) when working with code in this repository.

---

## 前端工程规范

本目录存放生产环境前端代码。

代码必须面向真实浏览器、真实用户、不可靠网络、并发交互场景设计，并兼顾长期可维护性。

---

## 1. 前端架构

**推荐依赖流向：**
页面 → 业务模块 → 组件 → 自定义钩子 / 应用逻辑 → 状态层 → API 请求客户端

禁止把组件作为承载核心业务逻辑的主要层级。

## 2. 状态分类

新增状态前，先对状态做归类。

### UI 状态（界面状态）

示例：
弹窗开关、选中标签页、输入框临时内容、悬浮态、本地交互状态
👉 优先使用组件本地状态。

### Client State（客户端状态）

示例：
登录鉴权上下文、应用偏好设置、客户端业务流程状态
👉 适合使用 Zustand 管理。

### Server State（服务端状态）

示例：
用户信息、订单、商品、后端返回权限
👉 **不要直接把服务端数据复制一份存到 Zustand。**

### Derived State（派生状态）

如果一个值可以由现有状态经过确定性计算得出，不要额外新建一份状态数据源。

## 3. Zustand 状态库

每一个 Store 必须明确定义：

- 状态归属
- 状态修改权限归属
- 重置逻辑
- 初始化逻辑
- 持久化策略
- 异步生命周期
- 错误处理语义

禁止用一个全局大 Store 存放互不相关的业务模块。

## 4. Zustand 异步操作

Store 里每一个异步动作，都必须考虑：

- 重复请求
- 过期响应
- 请求先后顺序错乱
- 请求取消
- 超时
- 重试机制
- 状态重置
- 组件卸载
- Store 状态过期

针对搜索、筛选、分页这类场景：

> 请求 A 发起 → 请求 B 发起 → 请求 B 先返回 → 请求 A 后返回
> 必须安全处理该场景。
> 旧的请求返回结果，**不允许覆盖更新更新的状态**，除非业务明确需要这么做。

## 5. React Effect 副作用

`useEffect` 仅用于和外部系统做同步。

以下场景不要滥用 effect：

- 派生值计算
- 简单运算
- 事件处理
- 可以直接初始化完成的状态

写 effect 之前自问：

> 这个副作用是在和哪个外部系统做同步？
> 如果答不上来，就要重新思考实现方案。

## 6. React 渲染

需要重点考量：
状态归属、组件划分边界、渲染频次、高开销计算、长列表、订阅监听

不要无脑添加：
`useMemo` / `useCallback` / `React.memo`
性能优化必须要有明确客观依据。

## 7. 异步 UI

所有异步交互流程，要覆盖这些状态：
`空闲(Idle)`、`加载中(Loading)`、`成功(Success)`、`空数据(Empty)`、`错误(Error)`、`刷新中(Refreshing)`、`已取消(Cancelled)`、`数据过期(Stale)`

不是每个页面都需要全部状态，但核心业务流程**不能只简单区分加载 / 成功两种状态**。

## 8. 浏览器环境可靠性

假设会发生以下各类情况：
用户刷新页面、多标签同时打开、请求被中断、网络变慢、网络断开、浏览器恢复缓存状态、Token 过期、用户重复点击、请求过程中组件卸载。

不要假设浏览器生命周期永远按理想线性顺序执行。

## 9. 身份鉴权

前端鉴权状态只负责用户交互体验。
**权限判定的权威来源永远是后端。**

永远不要把浏览器中拿到的 `isAdmin === true` 当作真实权限依据。

## 10. 表单

表单需要完整考虑：
校验逻辑、后端校验、重复提交、请求 pending 状态、错误信息映射、表单脏状态、重置、取消操作、乐观更新。

合适场景下阻止重复提交。
**不能只靠禁用按钮来防止重复提交。**

## 11. API 错误处理

前端要区分错误类型：
表单校验错误、身份鉴权错误、权限不足、资源不存在、冲突错误、业务逻辑错误、网络错误、超时、未知错误。

禁止把后端原始报错信息直接展示给终端用户。

## 12. 性能优化

优化前先定位真实瓶颈。
排查方向：
网络请求瀑布流、渲染频率、打包体积、长任务、高开销计算、长列表、图片、内存占用。

没有实际证据或充分技术理由，不要随意增加缓存记忆逻辑。

## 13. 无障碍访问（A11y）

生产环境 UI 必须兼顾：
键盘导航、语义化 HTML、焦点管理、标签说明、禁用状态、加载状态、错误提示播报、读屏器适配。

无障碍是功能正确性的一部分。

## 14. 前端安全

前端代码严禁泄露：
密钥、私有 API 密钥、服务端凭证、内部基础设施信息。

把 URL 参数、`localStorage`、`sessionStorage`、用户输入全部视作不可信数据。

## 15. 前端 “完成” 定义（DoD）

前端变更提测完成前必须确认：

- 交互行为验证完毕
- TypeScript 类型检查通过
- Lint 代码检查通过
- 相关测试用例执行通过
- 异步生命周期逻辑已评审
- 竞态条件问题已考虑
- 加载 / 错误 / 空数据状态全部覆盖
- 无障碍访问已考量
- 评估性能影响
- 不夹带无关重构改动

***

### 补充术语小注

- **Race conditions / 竞态条件**：多个异步请求时序错乱引发 bug
- **Derived State / 派生状态**：由其他数据算出来，不单独存源
- **Optimistic updates / 乐观更新**：不等接口返回，先更新界面，失败再回滚
- **Stale**：数据 / 响应过期陈旧
- **Definition of Done(DoD)**：交付完成标准
