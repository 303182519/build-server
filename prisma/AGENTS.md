# 数据库工程规范

## 1. 适用范围

本规范适用于 Prisma 数据模型定义文件以及 MySQL 数据库迁移脚本。

## 2. 数据库是生产环境系统

需默认以下前提：

- 数据库已存在生产业务数据
- 数据表数据量可能很大
- 迁移操作可能触发表锁
- 旧版本应用程序仍可能在线运行
- 回滚操作实现难度较高

## 3. 修改数据模型前

需核查以下内容：

- Prisma 模型定义
- 迁移历史记录
- 索引配置
- 约束条件
- 外键关联
- 可空字段设置
- 现有业务查询模式
- 现存数据的业务预设

## 4. 迁移安全准则

**严禁默认：本地运行正常 = 生产环境安全**

需评估：

- 数据表体量
- 锁表持续时间
- 索引创建开销
- 数据类型转换风险
- NULL 空值情况
- 重复数据风险
- 服务部署执行顺序
- 对旧版应用的兼容性

## 5. 扩缩容变更模式（扩展‑收缩模式）

高风险变更优先遵循流程：
**字段 / 能力扩展 → 部署兼容旧版的业务代码 → 执行数据迁移 → 切换业务逻辑行为 → 清理废弃字段 / 能力**

禁止直接做出会导致旧版应用立刻报错失效的变更。

## 6. 破坏性操作

无明确授权，禁止执行以下操作：

- 删除数据表（DROP TABLE）
- 删除数据列（DROP COLUMN）
- 破坏性数据迁移
- 不可逆的数据类型转换
- 删除关键约束

## 7. 索引设计

新增或删除索引前，需考量：

- 业务查询模式
- 字段基数（区分度）
- 写入性能损耗
- 存储空间占用
- 迁移执行成本

索引必须用于解决明确的查询访问性能问题。

## 8. 查询安全

需评审：

- N+1 查询问题
- 返回结果无上限的查询
- 超大结果集查询
- 缺失必要索引
- 排序结果不稳定
- 分页逻辑

## 9. 事务使用

事务用于保障业务数据不变性，不可滥用。
需要考虑：

- 事务隔离级别
- 锁竞争问题
- 事务执行时长
- 事务内部是否包含外部调用

## 10. 数据库交付完成标准

交付前评审项：

- 数据模型定义
- 迁移脚本
- 现有数据兼容性
- 索引配置
- 约束条件
- 事务行为逻辑
- 查询性能
- 部署版本兼容性
- 回滚 / 向前修复方案
- 相关测试用例

### 术语小注解

1. **Expand / Contract**：行业叫法「扩展‑收缩模式」，零停机数据库变更标准流程，先加字段兼容旧代码，迁移完数据，再删掉旧字段。
2. **cardinality**：基数，索引字段的数值区分度，比如性别字段基数低，用户 ID 基数极高。
3. **invariants**：不变性，业务必须永远成立的数据规则。
4. **rollback/forward strategy**：回滚 / 向前修复策略，迁移失败时，要么回退，要么向前执行修复脚本。
5. **unbounded queries**：无边界查询，不带分页、会一次性读取全表大量数据的 SQL。
