This file provides guidance to AI coding agents (Codex / Claude Code 等) when working with code in this repository.

---

## 数据库工程规范

将数据库表结构与生产数据视作核心基础设施。

数据库迁移的风险高于应用代码变更。

---

## 1. 表结构变更前检查

核查项：

- 当前 Prisma Schema 模型定义
- 迁移历史记录
- 索引
- 唯一约束
- 外键约束
- 字段可空配置
- 现有业务查询语句
- 受影响的服务
- 受影响的接口调用方
- 生产数据的实际业务预设

## 2. 迁移安全准则

切勿默认：**本地迁移成功 = 生产环境迁移安全**

评估要点：

- 数据表体量
- 锁表时长
- 索引创建开销
- 字段重写操作
- 数据类型转换
- 发布部署顺序
- 向后兼容性
- 回滚方案

## 3. 破坏性变更

以下操作必须获得明确授权才可执行：

- 删除表（DROP TABLE）
- 删除字段（DROP COLUMN）
- 破坏性数据迁移
- 删除唯一约束
- 删除外键约束
- 不可逆的字段类型修改

## 4. 扩缩容式表结构演进（Expand / Contract）

高风险表结构演进优先遵循流程：
**字段扩容新增 → 发布兼容旧版本的应用代码 → 迁移存量数据 → 切换应用业务逻辑 → 清理废弃字段**

滚动发布期间，禁止破坏旧版本应用的正常运行。

## 5. 查询安全

代码评审关注：

- N+1 查询问题
- 返回结果无上限的查询
- 缺失必要索引
- 多余联表 Join
- 查询冗余字段
- 分页逻辑
- 排序逻辑
- 过滤条件

可以交由数据库高效完成的操作，不要在应用层循环处理。

## 6. 数据库事务

事务用于保障业务不变性（业务数据一致性）。

示例场景：

> 
> 创建订单 + 生成订单项 + 库存扣减
> 当业务域有一致性要求时，上述操作必须作为一个完整一致性边界处理。

## 7. 并发处理

存在并发请求会篡改校验结果时，**绝对不要只使用：查询 → 业务校验 → 更新** 这套模式。

可选方案：

- 原子更新语句
- 数据库唯一约束
- 事务隔离级别
- 行锁
- 乐观并发控制

## 8. 分页

禁止查询返回无上限数据集。
大数据集场景评估：

- 游标分页
- 依托索引的偏移分页
- 稳定排序规则

分页必须具备确定性排序条件。

## 9. 生产数据注意事项

不要认为测试数据可以等同于真实生产数据。
迁移前需要考虑：

- NULL 空值情况
- 孤立脏数据
- 重复数据
- 遗留异常数据
- 数据表大小
- 历史存量记录

## 10. 数据库工作完成标准（Definition of Done）

数据库相关工作收尾前完成全部检查：

- Schema 模型校验完成
- 迁移脚本已评审
- 索引方案已评审
- 约束配置已评审
- 事务需求已评审
- 并发场景已评审
- 对生产数据的影响已评估
- 部署发布顺序已确认
- 回滚 / 向前修复预案已准备
- 相关测试执行完毕

### 术语小注

1. **Expand / Contract**：数据库领域经典「先扩后缩」发布模式，先新增兼容字段，全量代码上线迁移完数据后，再删除旧字段，实现零停机无损改表。
2. **unbounded queries**：无边界查询，没有 limit 限制，会拉取全表数据，极易造成数据库 OOM。
3. **business invariants**：业务不变性，指业务规则必须永远成立的数据约束。
4. **cursor pagination**：游标分页，对比 offset 偏移分页，适合海量数据，性能不会随页码增大衰减。
5. **rollback / forward strategy**：回滚（rollback）：出问题撤销变更；向前修复（forward）：无法回滚时，用新迁移脚本修复问题，生产数据库迁移很多场景不支持回滚。
